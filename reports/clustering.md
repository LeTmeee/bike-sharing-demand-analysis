# Clustering Analysis：每日共享单车需求模式（扩展二）

研究问题：能否从每日24小时租赁曲线中识别不同的需求模式？本模块延续原
proposal 的解释性 EDA 目标；聚类用于事后描述已观测日期。

## 复现

在项目根目录运行：

```powershell
python -m pip install -r requirements.txt
# 若尚无处理数据，先运行01审计与02数据准备；已有数据无需重建。
python scripts/07_clustering.py
python -m unittest discover -s scripts -p 'test_*.py'
```

支持 `--input`、`--tables-dir`、`--figures-dir`、`--seed`、`--n-init`、
`--max-k`，默认路径按脚本位置定位，因此也可从其他目录运行。
个人实验可指定独立输出目录。同名 `07_*` 产物在重跑时覆盖。
执行失败返回非零状态；旧文件可能仍在，应检查退出状态和本次元数据。

新增依赖为 scikit-learn 与直接使用的 threadpoolctl。此次实际使用系统
Python 3.11.9、pandas 2.3.3、NumPy 2.1.3、scikit-learn 1.7.2、
Matplotlib 3.10.3；旧 `.venv` 未在此次验证。完整环境记录在
`outputs/tables/07_run_metadata.json`。不同软件/数值库版本可能改变边界日期标签；
依赖采用最低版本约束而非完整环境锁定。

本机Windows初次运行出现joblib无法探测物理核数、回退到逻辑核的提示，
但脚本正常退出。后续验证在当前PowerShell进程设置
`$env:LOKY_MAX_CPU_COUNT='1'`，避免该环境提示；脚本本身已限制数值运算线程。

## 特征与模型选择

- **raw：规模与形状。** 每日按00–23时排列的24个原始 count。
- **share：形状为主。** 每小时 count / 该日24小时总量；每行和为1。
  每个日期等权，较高日总量不会在归一化后直接主导距离。

两种表示均不逐小时使用 StandardScaler：小时特征已有共同单位，保持相同权重，
避免放大低方差凌晨小时的差异。此处是对早期讨论中建议标准化步骤的明确细化。
需求占比仍可能在低总量日更不稳定；同样 share 不代表同样供给需求。

KMeans 只使用24个小时特征。`casual`、`registered`、用户占比、`log1p_count`、
每日总量、复核标记及日期/天气字段均不作为额外聚类输入。
每日总量只用于构造 share、处理零分母、汇总及数字标签排序。
工作日、季节、天气关联是拟合后的解释结果，不是聚类的先验标签。

默认参数为 `random_state=18`、`n_init=20`、`init='k-means++'`、
`algorithm='lloyd'`、`max_iter=300`、`tol=1e-4`，数值运算限制为1个线程。
先计算K=1的 inertia 作为参照，对K=2–6计算全样本欧氏 silhouette。
若样本数/不同曲线数不足，自动缩小候选范围；没有有效候选时停止。
在每种表示内部按最高 silhouette 选择K，精确并列时取较小K，再明确拟合最终模型。
数字 cluster ID 按该群平均日总量升序排列；两种表示的同号标签没有对应关系。

inertia 随K增加通常下降，仅作肘部图依据；不自动声称存在唯一肘点。
原始值与占比单位不同，不能直接比较两者 inertia 的大小。
silhouette 也是相应距离空间中的内部指标，两种表示的分值差异不能证明某种表示
更接近真实类别。share 作为主分析，是研究目标上的选择。

| K | raw silhouette | share silhouette |
| --- | ---: | ---: |
| 2 | 0.3453 | **0.6309** |
| 3 | 0.3966 | 0.3751 |
| 4 | **0.4105** | 0.3366 |
| 5 | 0.4070 | 0.3238 |
| 6 | 0.3518 | 0.1984 |

share 从K=1到2的 inertia 下降70.14%，之后到3只再降14.87%，
与选择两组的结果一致。raw 的K=4与5分值接近（差0.0035），
四组属于本规则的结果，不宜解释为唯一可靠的自然分类。
参数语义参考官方 [KMeans 文档](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.KMeans.html)
及 [silhouette 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.silhouette_score.html)。

share 第1组在08时与17–18时出现尖峰，第0组约12–16时较宽。
07–09时需求占比两组分别为7.19%与22.39%；10–15时占比为47.26%与23.04%。
这些时段比例为先逐日计算占比、再对日期等权平均；
不是先汇总租赁量再计算的加权比例。曲线图同时展示平均原始量与平均逐日占比。

两种表示的 adjusted Rand index 为0.3536；标签交叉表显示规模拆分改变了分组，
支持同时报告两种视角。不能把该值当作独立验证准确率。
两种表示的峰值和名称均来自实际结果，不能据此直接认定租赁目的为通勤或休闲。

天气用当日观测小时的唯一众数描述；出现并列众数时保存为空，在分布图/表中
标记为 `ambiguous`，不任意挑选较小编码。纳入日有15日天气众数并列。
保留 `weather_modal_share` 表示众数占比；单个主天气码会丢失日内变化，
稀有天气4可能出现于某些小时但没有成为完整日的主天气，不能据图推断其需求效应。
season/weather 保留来源编码；weekday 为周一0至周日6。
连续天气字段按观测小时取日均值，单位沿用原始数据。

## 解释限制与验证

完整日排除存在选择偏差：季节编码1只保留80/114日（70.18%），而其他季节
保留97.37%–98.25%；2011年保留194/228日，2012年220/228日。
完整日期之间仍有序列相关，且每月20日以后没有标签，结果不能代表全部日历天。
元数据分布未控制年份、季节和天气混杂，不构成因果效应或显著性检验。

KMeans采用欧氏距离和凸形中心近似，固定时钟对齐，不允许峰值随时间平移；
极端需求可能影响raw结果，平均曲线掩盖群内差异。
一次固定种子加多次初始化提供可复现结果，但未做多随机种子/跨年度稳定性评估。
silhouette 在拟合数据上选择K，属于探索性的内部评价，没有独立保留集验证。

这些标签需要看到整天的真实需求后才能产生，不能直接作为当天提前预测的输入。
未来若用于需求预测，必须在训练时间窗内拟合归一化/聚类与特征工程，
按时间评估，并确保目标时段的真实需求没有进入输入；`casual + registered = count`
仍然是明确的目标泄漏来源。没有生成预测或竞赛提交文件。

发布前复核已通过06—09模块共21项测试，其中07聚类模块含9项，覆盖缺小时/整日、
非法输入、天气并列、零总量、覆盖保护、占比缩放不变性、重复曲线、
确定性选择与完整输出一致性。对真实数据重复运行并比较生成文件校验和，
核对标签/指标/图表；图表已经人工目视检查。
本报告中的数值是本次结果快照，重跑新数据或参数后需人工更新本报告。
